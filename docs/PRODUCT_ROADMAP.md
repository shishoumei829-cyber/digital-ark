# 数字方舟 · 产品打造路线图

> 一句话目标：用户通过训练能明显感觉数字人越来越像自己，陪护对象感受到可信、克制、持续的陪伴。

## 版本定义

| 版本 | 目标 | 当前状态 |
|------|------|----------|
| **V0.1** | 页面结构正确：双 App、训练三栏、五模块、静态交互 | ✅ 基本完成 |
| **V0.2** | 可点击演示：模拟反馈、进度变化、授权流程可走 | 🔄 进行中（本次加强校准与总览） |
| **V0.3** | 真实数据 MVP：5–10 人真实训练、LLM 回复、画像持久化 | 部分具备（本地 LLM + 345 题 + 存储） |
| **V0.4** | 封闭测试：留存、很像比例、授权意愿、付费意愿 | ⬜ |

## MVP 闭环（第一版产品只证明这一件事）

```
创建数字人 → 基础资料 → 五类训练 → 试聊校准 → 授权陪护对象 → 陪护端聊天 → 一次主动问候
```

| 步骤 | 能力 | 代码/入口 |
|------|------|-----------|
| 1 创建 | 称呼 + 男/女形象 + 自训设定 | `POST /training/setup` · 创建向导 |
| 2 资料 | 简介、重要的人 | `training_setup.json` |
| 3 五类训练 | 音色/记忆/关系/情感/认知 | `/training/*` · 主页情境答题 |
| 4 试聊校准 | 像/不像 + 哪里不像 + 我会怎么说 | `POST /chat/feedback` · 对话 Tab |
| 5 授权 | 陪护对象列表与撤销 | `companion_authorization.json` · 我的/伦理面板 |
| 6 陪护聊天 | 知情同意 + 对话 | `companion.html` · `/companion/chat` |
| 7 主动问候 | 克制、基于记忆 | `ProactivityEngine` · 待产品化文案 |

**第一版不追求**：永生叙事、完全复刻、万能 AI。

## 训练端三栏（产品职责）

### 对话（p0）— 校准，不是聊天

- 自由试聊 + 场景输入
- 反馈：`不像我` / `有点像` / `很像我`
- `哪里不像`：7 类偏差标签
- `我会怎么说` → 写入 `feedback_learning` + CAPS 校准
- **可见变化**：`persona_changelog` + Toast/卡片展示系统反馈

### 训练（p1）— 总览 + 五模块

- 完成度圆环、五模块进度
- 今日建议、最近更新、下一步推荐 → `GET /training/dashboard`
- 各模块：任务 → 输入 → 提交 → 反馈 → 更新（逐步产品化）

### 我的（p7）— 生命周期

- 状态：草稿 / 训练中 / 可试聊 / 可陪护
- 授权、资料、版本记录（changelog）
- 伦理与边界（已有基础）

## 产品护城河（外显）

> **不是五个训练模块**，而是：每一句话都能追溯到五层各自起了什么作用。

用户可见：

- 试聊每条回复下：**为什么这样回应**（核心 / 情绪 / 记忆 / 关系 / 表达）
- **它从我哪里学来的**（训练模块、先例、试聊校准）
- **和普通 AI 有什么不同**（五层约束，非通用模板）
- 校准后：**哪一层被更新**（见变更卡片 + `layer_updates`）

实现：`lib/layer-explanation.js` · `GET` 对话返回 `layer_explanation` · 训练总览五层圆环。

## 核心产品原则（必须守住）

1. 不是普通 AI 聊天，是「像这个人」
2. 不宣传「复活死人」
3. 每次训练/校准要让用户**看见数字人变了**
4. 主动陪伴是核心，不是附件
5. 授权与边界是体验的一部分
6. 陪护对象情绪安全优先于技术炫技

## V0.4 核心指标

- 平均训练/校准次数

- 真实亲友授权率
- 付费意愿（访谈）
